## 联调中修复

1. Headscale 读取节点时会掩码预授权密钥。新记录保存并核对不可变预授权 ID；旧记录兼容严格格式的掩码前缀，避免误判合法绑定。
2. 用户提供的 MeshAgent Linux 二进制需要 `-install`。`-fullinstall` 返回成功但未安装，安装 hook 已更正并检查服务运行状态。
3. SSH 服务提供多种主机密钥时，中心必须同时限定所固定密钥的协商算法，否则可能选中另一把合法主机密钥而校验失败。已修复，并让终端集成测试提供多把主机密钥以覆盖此情况。
4. 临时 HTTPS 证书改用浏览器支持的 P-256；设备 Ed25519 身份不受影响。生产证书由部署环境提供。

修复后执行 `go test -race ./...`、`go vet ./...` 和 Python 编译检查，均通过。

## 自动 SSH 初始化追加验收

同日经用户授权，在同一 Debian 13 / N2840 测试机执行新增自动 SSH 初始化流程。未启用 OverlayFS 或重启，未修改 root 的 SSH 授权文件。

- 临时中心 `terminal.nodes` 为空，没有手工 SSH 私钥挂载；中心动态使用 SQLite 中生成的每节点登录密钥与固定主机公钥。
- 初始化自动登记 SSH 配置、创建 `nodehub-maint`，安装公钥并确认；随后启动 Agent。维护账号 UID 非零，仅属于自身用户组，未加入 sudo 组或新增 sudo 规则。
- 实测 home 与 `.ssh` 为 root 拥有、755，授权公钥文件 root 拥有、644；初始化进度文件 root 拥有、600。
- 真实 Chromium 浏览器登录 NodeHub 并打开终端，系统命令返回 `nodehub-maint` 和正确主机信息；调整窗口及关闭会话通过，无脚本或 CSP 错误。
- 再次执行相同初始化命令成功；中心登录私钥与主机公钥摘要保持不变，没有创建新节点或轮换身份。
- 中心进程重启后，重新启动测试 Agent 并等待在线，浏览器终端再次通过，确认 SQLite 登录身份恢复正常。恢复测试脚本需先等待 Agent 在线并刷新状态，再打开终端；中心刚重启时按钮暂时禁用符合预期，不能用浏览器固定 30 秒等待代替 Agent 就绪检查。
- Agent 单次服务内存观测约 6.2 MiB，不代表长期性能指标。
- 完整 `go test -race ./...` 通过，包含自动登记后终端网络链路。此前因临时端口权限未执行的集成测试已补跑。

测试完成后保留维护账号、公钥及中心数据库记录；临时中心与回环转发停止，NodeHub Agent 停止并恢复为不开机自启，Tailscale / MeshAgent / SSH 保持运行。此前关于临时中心地址迁移的限制仍适用；维护账号授权依赖该中心数据库中的私钥，部署新中心前不要删除或公开这份数据库。未把实际地址、设备编号、令牌或私钥回填到公开示例。
