## 1. 目标与边界

未来按需采集系统资源、服务健康及业务状态，支持断网后有限补传。远程终端、文件操作继续由 MeshCentral 提供，采集接口不接受任意命令。

初始候选数据包括 CPU 使用率、内存、磁盘空间、系统运行时间和指定服务状态。具体指标、频率、保留期和告警均待确认，不默认收集文件内容、密码或完整日志。

## 2. 通信方案建议

采用 HTTPS + 每设备 Ed25519 身份 + 短期不透明会话令牌。先用私钥证明设备身份，再通过 HTTPS 携带会话令牌批量上报。该方案暂不作为已确认协议。

1. 每设备独立私钥在首次启动时生成，保存于 `/data`，中心保存通过激活授权绑定的公钥及 key ID。不能仅接受请求中任意附带的公钥。
2. 客户端先验证 HTTPS 服务身份，向中心申请短期挑战。
3. 中心生成安全随机、短期、一次性的挑战，绑定节点、公钥版本及认证用途，并限制申请频率和未完成挑战数量。
4. 客户端对有版本和明确编码的认证消息签名，内容包含挑战标识和值、节点身份、公钥版本和目标服务标识。
5. 中心依据已登记公钥验签，原子消费挑战，确认节点未被吊销后签发短期会话令牌；并发重试与响应丢失的恢复行为在实现前明确。
6. 节点通过 HTTPS 的 Authorization 头携带令牌上报；令牌不放 URL、日志或指标标签。
7. 会话过期、中心重启或令牌失效后重新挑战认证；不按固定“每天一次”假设连接与会话生命周期。

会话令牌建议至少 32 字节安全随机数，中心只存摘要及节点、权限、到期时间和凭据版本。有效期候选为 15–60 分钟，最终根据规模和吊销需求选择。节点会话令牌优先只放内存，重启后用私钥重新认证。

中心每次上报校验节点状态、会话有效期、权限与请求大小。吊销节点或密钥时同时使关联会话失效，不能只阻止下一次登录。该方案的 Bearer Token 在有效期内被窃取仍可冒用，不等于每个请求都有私钥持有证明。

不自行实现 X25519 密钥交换或在 HTTPS 上重复设计 AES-GCM 消息加密。TLS 已承担传输加密与完整性保护；未来确有跨不可信中转的端到端加密需求时另行设计。mTLS 可作为替代方案，暂不引入证书签发与轮换体系。

## 3. HTTPS 如何认证服务器

客户端默认不额外内置中心应用层公钥，也不固定服务器叶证书公钥。使用 Debian CA 信任库，验证证书信任链、有效期以及预配置中心域名的匹配关系，禁用跳过校验和降级到 HTTP 的行为。客户端仍持有 CA 根证书这一信任基础，并非没有任何预置信任。

中心地址来自可信部署配置或激活文件，不能由未认证的网络响应任意替换。含凭据请求不跟随跨主机重定向。首次启动网络与系统时间须满足证书验证要求，不能因时间错误关闭校验。

普通 DNS 篡改或网络监听，在攻击者无法提供受信且匹配目标域名的证书时不能绕过校验。CA 错误签发、客户端信任库被修改、受信 TLS 解密代理或服务端密钥泄露仍会改变安全边界。

若采用私有 CA，需安全预置该 CA；若未来选择公钥固定，需预置备用密钥及轮换恢复机制。当前建议不启用固定，避免正常证书轮换导致海外设备失联。

若 TLS 在自有反向代理终止，代理属于信任边界，可以看到令牌和数据；代理到中心走受控本机网络、隔离网络或经验证的 TLS。机器接口不能被 Authelia 交互登录拦截。未经特殊设计，本方案不提供绕过 TLS 终止代理的端到端机密性。

## 4. 上报与离线恢复

- 客户端按可配置周期采样，复用 HTTPS 连接并批量发送；先依据真实规模评估，不假设“工业级必定不能逐条签名”。
- 每批含协议版本、节点 ID、批次 ID、采样时间和指标；中心保存接收时间。设备时钟不准时明确标注，不能用客户端时间判断身份有效性。
- 批次 ID 用于去重，实现至少一次提交；同一 ID 不得静默接受不同内容。去重不能阻止持有有效会话令牌的攻击者构造新请求。
- 明确处理成功、重复批次、限流、认证失败和数据格式不支持的响应。
- 网络失败指数退避并加随机抖动；队列按容量和数据年龄设上限，超限按既定规则丢弃并记录数量。
- 待补传数据在 `/data` 中有限保存，限制磁盘写入与总量，避免长时间断网写满持久分区。具体格式和写入策略待定。
- `/data` 挂载失败时不创建新身份，也不向根目录写入无限临时队列。

## 5. 服务端存储与生命周期

- 身份、密钥版本、会话和指标逻辑分离；不将“已有中心 SQLite”推导为“无限历史指标都放同一数据库”。
- 根据节点数、采样间隔、指标数及保留期估算写入和容量后，再选择指标存储与聚合清理策略。
- 设备失联、采集异常、Headscale 离线和 MeshCentral 离线分别展示，不能互相替代。
- 密钥轮换需有效旧凭据或管理员重新授权；设备被盗或密钥泄露时支持吊销。身份重建按新激活流程注册为新序列号，旧档案保留，不提供节点删除或旧档案恢复；不能仅以 `/data` 是否存在判断现有服务身份是否有效。
- 客户端升级、根目录 OverlayFS 维护、配置持久化和版本兼容需另行设计。

## 6. 未来实现前的验证

- 非法证书、错误域名及跨主机重定向不会导致凭据泄露。
- 挑战重放、公钥替换、跨服务重用认证消息被拒绝。
- 过期会话、已吊销节点及旧密钥关联会话被拒绝。
- 断电重启身份不变；重复上报去重；断网队列不超出磁盘预算。
- 在目标硬件测量签名、验签、TLS、采样与写盘的总开销，依据结果决定优化。
