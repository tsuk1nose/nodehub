# Node Hub 初版需求与架构规范

[English](../../specification.md) | 简体中文

版本：1.2　日期：2026-11-12　状态：已确认需求，初版开发中

本文为当前正式规范，取代 `design-discussion.md` 中的历史建议；实现进度以 README 为准。未来采集方案单列在 `telemetry-draft.md`，当前不实现。

## 1. 目标与规模

统一登记 Debian 13 边缘节点，编排 Headscale 与 MeshCentral 接入，展示连接状态，提供对应 MeshCentral 的跳转入口。初期几百台，以 x86 Intel N2840 为主。未来几千至几万台的扩展留待实际需要时设计。

Headscale 与 MeshCentral 由用户独立部署，已完成首次真实接口联调。初期各服务同机运行 Docker，后期可通过配置修改服务地址拆分。域名、证书及反向代理由用户管理，不在本项目当前部署设计范围。

## 2. 技术与组件

| 组件 | 选择及职责 |
| --- | --- |
| 中心后端 | Go、标准库 net/http；登记、认证、编排、同步、查询 |
| 管理前端 | Vue 3、TypeScript、Vite；构建为静态文件，由 Go 服务提供 |
| 数据库 | SQLite、单中心实例、显式 SQL 与版本化结构 |
| Headscale | 0.29.7；管理 Tailscale 节点，开启内置 DERP 和客户端校验 |
| MeshCentral | 1.3.1；设备维护、终端和文件操作 |
| 交付 | Dockerfile、Compose、配置示例及启动脚本 |

不引入 Redis、消息队列或微服务。Headscale 后续可能发生破坏性更新：固定版本，接口集中适配，升级前验证注册、查询、关联及迁移。中心不代理或嵌入 MeshCentral 管理页面。

内置 DERP 设置 `derp.server.verify_clients: true`，不因 DERP 校验额外部署 tailscaled。若未来中心需要主动访问节点 Tailscale 地址，再独立评估服务端客户端。

## 3. 身份与凭据

节点唯一 ID、序列号、展示编号是同一个字段：12 位 `0–9`、`A–Z` 安全随机字符串，不另设 UUID，不提供改号。数据库唯一约束兜底，碰撞重新生成。节点 hostname 及两套上游名称均对应序列号；允许上游规范化名称大小写。

序列号不是秘密。节点首次请求前生成独立请求身份及认证凭据，先在本机落盘；响应丢失或中断重试须恢复原注册，不重复分配 ID 或消耗令牌限额。

初始化令牌通过文件注入镜像，有效期、允许注册次数均可配置；早期允许无限期、无限次数以复用镜像。支持撤销，服务器仅保存摘要，创建时仅显示一次秘密。同一设备恢复不额外计数。通用令牌不因单台成功而失效。

初始化恢复继续使用每节点独立安全随机 Bearer 凭据和 HTTPS，中心存摘要。可选原生 Agent 新增独立 Ed25519 挑战认证，不复用 SSH 登录密钥。长期指标采集仍不实现。所有凭据不写入日志和源码。

## 4. 配置与认证

中心配置文件包含监听地址、数据库路径、状态查询间隔、Web 登录配置，以及：

- Headscale 内部 URL、外部登录 URL、API key、目标 user ID 和标签。
- MeshCentral 内部 WebSocket URL、外部控制台 URL、自动化用户名与凭据、设备组 ID。
- 可选的经实机验证的 MeshCentral 设备直达 URL 模板。

内部地址可以使用 Docker 服务名，不能下发给节点。每个上游可单独设置 `tls_skip_verify`，默认 false，仅对中心访问其内部 HTTPS/WSS 生效，不影响节点或 Agent 的 HTTPS。中心配置文件由宿主机只读挂载，使用受限权限，不写入镜像。更新后重启中心；当前不实现热重载或自动凭据轮换。

默认开启单管理员登录，密码存 bcrypt 哈希，会话 cookie 使用 HttpOnly、SameSite 及可配置 Secure。可关闭本地登录以使用 Authelia；由部署方确保管理 API 无法绕过前置认证。节点机器接口独立使用注册或节点凭据，不走交互式登录。

## 5. 镜像与首次初始化

### 5.1 制作镜像

1. 完成业务程序与系统依赖安装配置；预装 Tailscale / MeshAgent 时不得提前注册。
2. 最后安装首次启动工具、服务、激活文件及受信安装脚本。
3. 确保模板无本机已注册身份、进度和完成标记，正确封装 machine-id / SSH 主机身份；具体 Debian 封装操作需实机验证。
4. 不在模板启动初始化，关机克隆。

### 5.2 克隆节点首次启动

1. 在根目录仍持久可写的阶段生成并保存本机请求身份和凭据。
2. 使用初始化令牌取得序列号，验证本机独立认证和恢复能力后删除本机激活文件。
3. 设置 hostname 与相关主机名配置。
4. 向中心申请短期、不可复用的 Headscale 预认证密钥，以序列号加入指定 Headscale。
5. 中心验证本机公钥、注册来源及外部节点 ID，保存关联。
6. 以序列号安装注册 MeshAgent，可靠确认 MeshCentral Node ID 与设备组后保存关联，不能仅凭同名自动绑定。
7. 完成所有初始化状态和默认服务目录写入，删除初始化凭据、程序和首次启动服务。
8. 通过经实机验证的配置方式启用下次启动的根目录 OverlayFS，然后重启。
9. 验证根目录 OverlayFS、hostname、服务连接及身份保留后确认完成。

注册与最终化分别记录。任何步骤失败不误报完成，重试保留已完成结果；最终清理必须考虑断电恢复。在工具删除后，通过已有远程维护通道或外部恢复介质继续，不在镜像中留下共享激活秘密。

## 6. 存储与启动

MeshAgent 整目录安装在 `/data/nodehub/meshagent`，挂载失败时仅 MeshAgent 不启动。Tailscale 和原生 Agent 身份及配置仍留在根目录默认位置，初始化时写入持久底层。不再安装顶层可写修复服务。hostname、machine-id 和 SSH 主机密钥也需跨重启保留且不能克隆共享。

`/data` 使用 CoW，具体文件系统待定；挂载失败不能阻止开机，Tailscale 和原生 Agent 仍可使用根目录身份启动；MeshAgent 依赖该挂载。依赖 `/data` 的生产任务可以降级或等待，不得写入未挂载的同名空目录。

CoW 与根目录 OverlayFS 分别设计。OverlayFS 的 upper/work 位置、是否重启清空、根目录维护模式尚待确定；运行期密钥变化、重新登录和服务升级不能仅依赖初始基线。初始化秘密放根目录时应在 OverlayFS 生效前删除；放 `/data` 时不受根目录删除遮蔽影响，但须确认真实挂载。

## 7. 同步与界面

每 60 秒批量查询上游连接状态，间隔可配置。持续监测离线和重新上线；首次发现在线、离线转在线及中心重启后对齐基础资料，地址等易变字段随状态结果刷新。原上游同步仅使用现有上游资料；可选 Agent 另行提供在线状态及系统版本、架构、版本号、运行时间，不保存历史指标。

两套连接状态独立：在线、离线、未绑定或未知、上游找不到记录。上游 API 失败显示同步异常并保留上次已知状态与成功同步时间，不能判成节点离线。最近可见时间明确按上游时间或中心成功观察时间展示，不声称是精确历史上线时刻。

界面包含节点序列号、注册时间、注册步骤与错误、两个上游外部 ID 和连接状态、最近可见时间及 Tailscale 地址。支持初始化令牌创建与撤销。MeshCentral 按钮跳转到对应设备，直达地址未验证前只提供明确标注的控制台入口。

## 8. 生命周期

不提供节点删除，旧档案和编号保留。重新刷机或重建身份以新授权注册为新节点，分配新序列号，不恢复或迁移旧档案。正常重启及未完成初始化恢复不创建新节点。

保留联动吊销需求：中心、Headscale、MeshCentral 均需拒绝旧身份访问。各上游结果单独记录，部分失败可重试，不误报整体成功。必须验证 MeshCentral 1.3.1 阻止旧 MeshAgent 重接入的方法；未经验证不提供虚假的吊销成功操作。重新注册本身不等于吊销旧身份，批量激活令牌仍可能允许申请新身份。

## 9. 可选原生终端（新增已授权范围）

在原项目内实现 Go Agent + xterm.js + 现有 SSHD。设备保持出站 WSS 控制连接，每个终端独立 WSS 数据连接，不在第一版实现多路复用。保留 MeshCentral 入口，新增 Agent 在线状态，不覆盖原有上游状态。

使用已登记节点身份授权绑定独立 Ed25519 公钥；挑战有时限并绑定连接。终端必须验证管理会话、Origin、设备权限及 SSH 主机公钥，SSH 私钥只留在中心，正常自动流程按节点生成并存入 SQLite；初始化通过独立恢复凭据上报并固定主机公钥，安装 root 的授权公钥，确认后动态启用终端，无需逐节点 JSON 配置或重启。终端直接以 root 执行，中心管理员具有节点完整维护权限；Agent 中继进程无需以 root 运行。第一版复用单管理员，不增加完整 RBAC。

连接、会话、输入输出缓冲及持续时间均有上限；输出待浏览器处理确认后继续。增加会话元数据与成功登录、设备接入事件审计。支持原生 Agent 停用，明确仅影响该通道，不冒充上游联动吊销。

Agent 私钥和系统服务在默认根目录路径，不依赖 `/data`；模板不带已生成私钥，初始化最终清理只移除初始化工具，保留常驻 Agent。实际配置、端点、安装和验证见 [原生终端说明](native-terminal.md)。本功能默认关闭，长期数据采集仍不实现。

## 10. 初版验收

- 可构建 Go 后端与 Vue 前端，Docker 提供中心单实例部署。
- SQLite 跨重启保留节点和令牌，提供一致性备份。
- 管理登录默认启用，可关闭；节点凭据无法访问管理 API。
- 12 位序列号唯一；注册响应丢失重试不重复登记或计数；限次、过期和撤销有效。
- Headscale 与 MeshCentral 配置可独立启用，缺失配置时明确展示。
- 状态查询失败不把在线节点误标离线；恢复后可继续同步。
- 同一镜像的不同设备身份独立；首次启动工具支持中断恢复及激活文件清理。
- 两个上游绑定、本地二进制 hook 安装与 Debian 13 / N2840 原生终端已完成首次实机联调；Docker 容器运行、OverlayFS、克隆镜像完整流程及联动吊销仍需验证或实现。详见实机联调记录。
